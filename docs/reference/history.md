# Mattrax: every repository and every version, indexed

A source-level audit of the Mattrax codebase across the `mattrax` organisation and `oscartbeaumont`'s personal repos. Every repo was cloned into a temporary workspace on 2026-11-07, the product versions were indexed by separate agents, and every claim below links to the exact commit and lines that support it.

**Why this exists:** Mattrax has been restarted many times. This is the map: what each repo is, which ones are alive, which are archaeological, what each version actually implemented, and where the bodies are buried.

## TL;DR

- **17 repositories** carry Mattrax code: 10 under `mattrax`, 7 under `oscartbeaumont`.
- **Active products:** `mattrax/mttx` (private, Rust/Axum + SolidStart, Apple-first) and `oscartbeaumont/mattraxe` (TypeScript/Effect). `mattraxe` now builds, deploys and covers the migrated management surface; see the status update at the end.
- **`mattrax/Mattrax` is no longer open source.** The default `banner` branch is a notice; the real code survives on historical branches (`main`, `v2`, `nx`, `sst`, `rust`).
- **The product has been rewritten at least 8 times** since the 2021 Go proof of concept. Each rewrite re-solved Windows enrollment; several threw away working Apple or policy work.
- **Apple MDM only became first-class in 2025** in `mttx` (APNs, SCEP, `.mobileconfig`, Declarative Device Management). Before that, Apple was mostly schemas and UI placeholders.
- **The recurring unfinished features are the same across versions:** policy delivery, device actions, app deployment, RBAC, invites, audit, CLI/agent, billing.
- **`configure` (Oct 2026)** is a small, self-contained MDM settings catalogue/exporter, not a server.

## Scope and method

Repositories were enumerated with `gh api orgs/mattrax/repos?type=all` and `gh api user/repos?affiliation=owner&visibility=all` (the org listing alone misses private repos and `mattraxe`). All 17 were cloned; historical branches were checked out as detached worktrees. Each version was indexed against its actual source, not its README. Line links point at the pinned commit for that snapshot.

Two repos are not product versions: `homebrew-tap` (empty placeholder) and `Mattrax2` (empty restart stub). They are included because they are part of the repository history.

## Version-by-version index

### 1. `windows_mdm` — the Go proof of concept (2018–2021)

**Ref:** `oscartbeaumont/windows_mdm@e52e28e` · **State:** dormant PoC, MIT, ~639 lines of Go.

A single HTTPS process that speaks just enough of MS-MDE and MS-MDM to enrol a Windows 10 device. Routes cover the landing page, an `ms-device-enrollment:` deep link, federated auth, ToS, `Discovery.svc`, `Policy.svc`, `Enrollment.svc` and `Manage.svc` ([`main.go:42-85`](https://github.com/oscartbeaumont/windows_mdm/blob/e52e28e50db7e2888bbedeb407fe0922666dcf69/main.go#L42-L85)). Discovery returns policy/enrollment URLs and an optional auth service ([`mde_discovery.go:16-64`](https://github.com/oscartbeaumont/windows_mdm/blob/e52e28e50db7e2888bbedeb407fe0922666dcf69/mde_discovery.go#L16-L64)); enrollment parses a CSR, signs a client cert and returns a hand-built WAP provisioning profile that installs the root/client certs and points the device at the management endpoint ([`mde_enrollment.go:47-106`](https://github.com/oscartbeaumont/windows_mdm/blob/e52e28e50db7e2888bbedeb407fe0922666dcf69/mde_enrollment.go#L47-L106), [`mde_enrollment.go:128-180`](https://github.com/oscartbeaumont/windows_mdm/blob/e52e28e50db7e2888bbedeb407fe0922666dcf69/mde_enrollment.go#L128-L180)). Management only acknowledges SyncML check-ins and never delivers policy or actions ([`mdm_manage.go:24-141`](https://github.com/oscartbeaumont/windows_mdm/blob/e52e28e50db7e2888bbedeb407fe0922666dcf69/mdm_manage.go#L24-L141)).

The code is deliberately unsafe: XML is regex-scraped rather than parsed, the CA private key is committed in `identity/identity.key`, every certificate gets serial `2`, fingerprints are SHA-1, auth is a literal `TODOSpecialTokenWhichVerifiesAuth`, and the provisioning profile's management URL points at a route that does not exist ([`mde_enrollment.go:91-118`](https://github.com/oscartbeaumont/windows_mdm/blob/e52e28e50db7e2888bbedeb407fe0922666dcf69/mde_enrollment.go#L91-L118), [`main.go:59`](https://github.com/oscartbeaumont/windows_mdm/blob/e52e28e50db7e2888bbedeb407fe0922666dcf69/main.go#L59)). The README itself says not to use it as a production reference and points to Mattrax ([`README.md:3`](https://github.com/oscartbeaumont/windows_mdm/blob/e52e28e50db7e2888bbedeb407fe0922666dcf69/README.md#L3)).

### 2. `Mattrax-Jan23` — first Rust rewrite (Jan 2023)

**Ref:** `oscartbeaumont/Mattrax-Jan23@9c46447` · **State:** early spike, single squashed commit.

One Axum binary serves the compiled SolidJS dashboard, an rspc API over `/rspc/:id`, and reserved Windows MDM paths ([`src/routes.rs:24-49`](https://github.com/oscartbeaumont/Mattrax-Jan23/blob/9c4644741b00046aa02044bb1b5ddbb8ee10a8a0/src/routes.rs#L24-L49)). The API is split into auth/tenant/user/device/policy routers ([`src/api/mod.rs:39-55`](https://github.com/oscartbeaumont/Mattrax-Jan23/blob/9c4644741b00046aa02044bb1b5ddbb8ee10a8a0/src/api/mod.rs#L39-L55)); auth uses Argon2 and a 1-day DB session ([`src/api/auth.rs:137-172`](https://github.com/oscartbeaumont/Mattrax-Jan23/blob/9c4644741b00046aa02044bb1b5ddbb8ee10a8a0/src/api/auth.rs#L137-L172)), and Prisma defines accounts, tenants, users, devices and policies ([`prisma/schema.prisma:90-114`](https://github.com/oscartbeaumont/Mattrax-Jan23/blob/9c4644741b00046aa02044bb1b5ddbb8ee10a8a0/prisma/schema.prisma#L90-L114)).

Windows is model-only: discovery, WS-Trust enrollment, XCEP policy and WAP provisioning are modelled with `yaserde` ([`src/mdm/win/soap/discovery.rs:3-115`](https://github.com/oscartbeaumont/Mattrax-Jan23/blob/9c4644741b00046aa02044bb1b5ddbb8ee10a8a0/src/mdm/win/soap/discovery.rs#L3-L115)), but the handlers are `todo!()` ([`src/mdm/win/mod.rs:11-29`](https://github.com/oscartbeaumont/Mattrax-Jan23/blob/9c4644741b00046aa02044bb1b5ddbb8ee10a8a0/src/mdm/win/mod.rs#L11-L29)). Tenant isolation is not implemented (`uid = "todo"`), stats are fabricated, and device/user/policy pages are stubs ([`src/api/tenant.rs:43-59`](https://github.com/oscartbeaumont/Mattrax-Jan23/blob/9c4644741b00046aa02044bb1b5ddbb8ee10a8a0/src/api/tenant.rs#L43-L59), [`web/src/pages/Devices.tsx:235-236`](https://github.com/oscartbeaumont/Mattrax-Jan23/blob/9c4644741b00046aa02044bb1b5ddbb8ee10a8a0/web/src/pages/Devices.tsx#L235-L236)).

### 5. `oscartbeaumont/Mattrax` + `Mattrax-api` — the one-binary scaffold (Dec 2023)

**Ref:** `oscartbeaumont/Mattrax@b12ab9c`, companion `Mattrax-api@be55cca` · **State:** pre-alpha, abandoned.

`Mattrax` is a single Axum binary with an embedded SolidJS SPA and a hand-rolled JSON API ([`src/api/mod.rs:80-99`](https://github.com/oscartbeaumont/Mattrax/blob/b12ab9ccf85177868b4f76bbd33d5c132236f5ab/src/api/mod.rs#L80-L99)). Persistence is SQLite through the private `besu` ORM, with four tables: account, session, tenant, user ([`src/db/mod.rs:17-25`](https://github.com/oscartbeaumont/Mattrax/blob/b12ab9ccf85177868b4f76bbd33d5c132236f5ab/src/db/mod.rs#L17-L25)). Auth is Argon2 + a Branca session cookie ([`src/api/auth.rs:100-172`](https://github.com/oscartbeaumont/Mattrax/blob/b12ab9ccf85177868b4f76bbd33d5c132236f5ab/src/api/auth.rs#L100-L172)). The novel part is `normi`, a normalised cache implemented twice in Rust and TypeScript ([`crates/normi/src/normalise.rs:30-105`](https://github.com/oscartbeaumont/Mattrax/blob/b12ab9ccf85177868b4f76bbd33d5c132236f5ab/crates/normi/src/normalise.rs#L30-L105)).

Despite the commit message "Add `ms-mdm` crate", there is no MDM code: the crate exports only an `OsEdition` enum ([`crates/ms-mdm/src/lib.rs:1-5`](https://github.com/oscartbeaumont/Mattrax/blob/b12ab9ccf85177868b4f76bbd33d5c132236f5ab/crates/ms-mdm/src/lib.rs#L1-L5)), and `db/devices.rs`, `db/policies.rs`, `db/applications.rs` are zero bytes. The companion `Mattrax-api` is a Next.js/T3 login service with email OTP, Drizzle/PlanetScale and SES; its licensing/installation/updater routers are empty files ([`src/server/api/routers/auth.tsx:72-189`](https://github.com/oscartbeaumont/Mattrax-api/blob/be55ccaaa38bdd3966fd4f0d97075e1e92fb987e/src/server/api/routers/auth.tsx#L72-L189), [`README.md:3`](https://github.com/oscartbeaumont/Mattrax-api/blob/be55ccaaa38bdd3966fd4f0d97075e1e92fb987e/README.md#L3)).

### 6. `Mattrax@nx` — Nx + one Rust Windows server (May 2024)

**Ref:** `mattrax/Mattrax@nx` (`ac0f2f1`) · **State:** WIP pre-release.

This is the first version with an end-to-end Windows enrollment path. A single Rust `apps/mattrax` binary handles TLS/ACME, MS-MDE/MS-MDM and an internal SQL bridge, while the SolidStart dashboard and tRPC API live in `apps/web` ([`apps/mattrax/src/api/mod.rs:96-108`](https://github.com/mattrax/Mattrax/blob/ac0f2f1ce6515297ef2d39aa663113f386a7cf78/apps/mattrax/src/api/mod.rs#L96-L108)). Enrollment validates the token, rewrites and signs the CSR, stores the device and returns a WAP provisioning profile ([`apps/mattrax/src/api/mdm/enrollment.rs:235-390`](https://github.com/mattrax/Mattrax/blob/ac0f2f1ce6515297ef2d39aa663113f386a7cf78/apps/mattrax/src/api/mdm/enrollment.rs#L235-L390)). The dashboard has Entra ID domain sync, groups/devices/policies/apps, and a visual policy composer ([`apps/web/src/api/rest/ms.ts:44-237`](https://github.com/mattrax/Mattrax/blob/ac0f2f1ce6515297ef2d39aa663113f386a7cf78/apps/web/src/api/rest/ms.ts#L44-L237)).

The fatal gap: enrollment leads to check-in, but policy delivery returns no SyncML nodes and actions are commented out ([`crates/mx-windows/src/policies.rs:15-78`](https://github.com/mattrax/Mattrax/blob/ac0f2f1ce6515297ef2d39aa663113f386a7cf78/crates/mx-windows/src/policies.rs#L15-L78), [`crates/mx-windows/src/actions.rs:3-138`](https://github.com/mattrax/Mattrax/blob/ac0f2f1ce6515297ef2d39aa663113f386a7cf78/crates/mx-windows/src/actions.rs#L3-L138)). Apple has no APNs/SCEP/check-in; Android is a "Hello Android" template; the CLI is `todo!()` ([`apps/mttx/src/cli/mod.rs:34-42`](https://github.com/mattrax/Mattrax/blob/ac0f2f1ce6515297ef2d39aa663113f386a7cf78/apps/mttx/src/cli/mod.rs#L34-L42)).

### 7. `Mattrax@sst` — AWS/SST alpha (Sep 2024)

**Ref:** `mattrax/Mattrax@sst` (`26208df`) · **State:** alpha checkpoint.

SST v3 provisions SES, an ECDSA P-256 CA, a cargo-lambda `mx-cloud` function, a mutual-TLS API Gateway for `manage.mattrax.app`, and CloudFront sites ([`sst.config.ts:129-147`](https://github.com/mattrax/Mattrax/blob/26208df930833974c0f32823b8fcf6b021bf0302/sst.config.ts#L129-L147)). The Windows chain is the most complete of the 2024 versions: `mx-manage` handles Discovery/Policy/Enrollment, and `mx-windows` performs a real desired-state merge with add/replace/delete and conflict tracking ([`crates/mx-manage/src/enrollment.rs:229-603`](https://github.com/mattrax/Mattrax/blob/26208df930833974c0f32823b8fcf6b021bf0302/crates/mx-manage/src/enrollment.rs#L229-L603), [`crates/mx-windows/src/policies.rs:178-323`](https://github.com/mattrax/Mattrax/blob/26208df930833974c0f32823b8fcf6b021bf0302/crates/mx-windows/src/policies.rs#L178-L323)). The dashboard is a full org/tenant app with tRPC, Entra sync, policies, deploys and audit tables.

But the cloud API constructs `db: todo!()` ([`apps/cloud/src/api.rs:22-27`](https://github.com/mattrax/Mattrax/blob/26208df930833974c0f32823b8fcf6b021bf0302/apps/cloud/src/api.rs#L22-L27)), self-host `create_device` computes IDs but never inserts, device actions return empty, and results handling is commented out ([`apps/mattrax/src/api/mdm.rs:103-135`](https://github.com/mattrax/Mattrax/blob/26208df930833974c0f32823b8fcf6b021bf0302/apps/mattrax/src/api/mdm.rs#L103-L135), [`crates/mx-windows/src/results.rs:3-68`](https://github.com/mattrax/Mattrax/blob/26208df930833974c0f32823b8fcf6b021bf0302/crates/mx-windows/src/results.rs#L3-L68)). Apple is explicitly "not supported yet" ([`apps/web/src/app/(dash)/o.[orgSlug]/t.[tenantSlug]/settings/enrollment.tsx:240-245`](<https://github.com/mattrax/Mattrax/blob/26208df930833974c0f32823b8fcf6b021bf0302/apps/web/src/app/(dash)/o.%5BorgSlug%5D/t.%5BtenantSlug%5D/settings/enrollment.tsx#L240-L245>)).

### 8. `Mattrax@main` / `@v2` — TypeScript-first rewrite (Oct 2024)

**Refs:** `main` (`21554bb`) and `v2` (`79cb0a0`). `v2` is 37 commits ahead of the shared base and is where the TS work happened; `main` is a rebased sibling with a later dependency/infrastructure pass.

`v2` is the point where the MDM core moved from Rust to TypeScript. One Cloudflare Worker serves the SolidStart SPA and the Windows MS-MDE SOAP endpoints; tRPC is transported as a "server function" over a custom streaming link; Drizzle talks to PlanetScale ([`apps/api/src/index.ts:56-93`](https://github.com/mattrax/Mattrax/blob/79cb0a075ecf22d4a682787564df25e55cf521e8/apps/api/src/index.ts#L56-L93), [`packages/trpc-server-function/src/index.ts:29-102`](https://github.com/mattrax/Mattrax/blob/79cb0a075ecf22d4a682787564df25e55cf521e8/packages/trpc-server-function/src/index.ts#L29-L102)). The branch adds an in-worker device-authority PKI: RSA-4096 CA, truststore, renewal cron and client-cert issuance ([`apps/api/src/authority/issue.ts:3-57`](https://github.com/mattrax/Mattrax/blob/79cb0a075ecf22d4a682787564df25e55cf521e8/apps/api/src/authority/issue.ts#L3-L57), [`apps/api/src/win/index.ts:119-238`](https://github.com/mattrax/Mattrax/blob/79cb0a075ecf22d4a682787564df25e55cf521e8/apps/api/src/win/index.ts#L119-L238)). The UI is rebuilt around tenants and blueprints with a URL-synced table state and a new sidebar/design ([`apps/web/src/components/Table/index.tsx:31-175`](https://github.com/mattrax/Mattrax/blob/79cb0a075ecf22d4a682787564df25e55cf521e8/apps/web/src/components/Table/index.tsx#L31-L175)).

Management is a stub: `Manage.svc` verifies the mTLS certificate and returns an empty response, with no SyncML session or commands ([`apps/api/src/win/index.ts:240-284`](https://github.com/mattrax/Mattrax/blob/79cb0a075ecf22d4a682787564df25e55cf521e8/apps/api/src/win/index.ts#L240-L284)). ## Supporting repositories

- **`mtls-proxy`** — DNS-driven mTLS terminator. A TXT record (`mtls:accept|<origin>`) selects the upstream; the proxy requires any client cert and forwards it as base64 DER in `X-Client-Cert`, then lets the backend verify it ([`cmd/main.go:148-188`](https://github.com/mattrax/mtls-proxy/blob/09e65a208fd293627d11abd677bce64cc2152484/cmd/main.go#L148-L188), [`cmd/main.go:242-244`](https://github.com/mattrax/mtls-proxy/blob/09e65a208fd293627d11abd677bce64cc2152484/cmd/main.go#L242-L244)). ## Cross-cutting findings

1. **The rewrites are the story.** 2021 Go PoC → Jan 2023 Rust/Prisma → Mar 2023 empty restart → Oct 2023 Axum hello world → Dec 2023 one-binary scaffold → May 2024 Nx → Sep 2024 SST → Oct 2024 TypeScript v2 → Jan 2025 Rust reset → 2025/26 `mttx` → 2026 `mattraxe`. Almost every generation re-solved Windows enrollment from scratch and left the previous policy/UI work behind.
2. **Windows was first, Apple became first.** Windows enrollment is implemented in 2021 (`windows_mdm`), 2024 (`nx`, `sst`, `v2`) and 2025/26 (`mttx`'s Go `windm`). Apple only becomes a real platform in `mttx` (APNs/SCEP/DDM); `mattraxe` then ports that protocol work into TypeScript packages.
3. **The same features are stubbed in every generation.** Policy delivery, device actions, app deployment, RBAC, invitations, audit logging, a working CLI/agent and billing appear as `todo!()`, "Coming soon", empty routers or no-op mutations in almost every version. The recurring failure mode is not protocol parsing; it is closing the management loop.
4. **Security debt is consistent.** Committed CA private keys (`windows_mdm/identity/identity.key`), plaintext CA keys in the DB (`Mattrax@v2`), fixed `TODOSpecialTokenWhichVerifiesAuth`/`CN=TODO` identities, SCEP without challenge/signature verification (`Mattrax@rust`), no RBAC in `mttx`, and no cert revocation in most versions.
5. **There are two live code lineages, not one.** `mttx` is the Rust-first, Apple-complete product with cloud licensing. `mattraxe` is the newer TypeScript/Effect product model with Enterprise/Platform/Whitelabel and a `ManagementBackend` abstraction. They overlap heavily but are not forks of each other.
6. **The public repo is now a tombstone.** `mattrax/Mattrax` advertises "no longer open source" on its default branch, while the historical branches remain readable and are the best record of the 2024 architecture.
7. **`configure` is the only small, finished artifact.** It has a narrow job (catalogue/search/export MDM settings) and does it without a backend. It is a useful reference for the Apple/Android/Windows schema shapes that the server versions repeatedly re-imported.
